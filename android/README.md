# Lievik for Android

A native Android client for [Lievik](../README.md): the same sources, channels,
curation queue, content builder, Ask, AI channel creation, activity, settings
and paid access as the web app, against the JSON/SSE API in
[`docs/API_V1.md`](../docs/API_V1.md). Local-first: the lists you browse come
from an on-device database, so they open instantly and work offline.

## Build and run

Toolchain (Android Studio's own):

```sh
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"   # JBR 25
export ANDROID_HOME="$HOME/Library/Android/sdk"
cd android
./gradlew assembleDebug testDebugUnitTest lint
```

- Gradle 9.7.1 (wrapper), AGP 9.4.1 (built-in Kotlin), Kotlin 2.4.20, KSP 2.3.12,
  compileSdk/targetSdk 37, minSdk 26.
- Debug APK: `app/build/outputs/apk/debug/app-debug.apk` (applicationId
  `today.cypherpunk.lievik.debug`, installs next to a release build).
- Install on the emulator: `adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk`.
- Against a local server: start the backend (`bin/rails s -p 3100 -b 0.0.0.0` in the
  repo root), then on the login screen open **Advanced** and set the server to
  `http://10.0.2.2:3100`. Plain http is allowed in debug builds only
  (`src/debug/res/xml/network_security_config.xml`).

### Strings

All UI text lives in `res/values*/strings_*.xml` in en, sk, cs and es. Do not edit
`strings_web.xml` / `strings_app.xml` by hand: they are generated by

```sh
/opt/homebrew/opt/ruby/bin/ruby android/tools/strings/generate.rb
```

`strings_web.xml` takes the web's exact wording from `config/locales/**` (the `WEB`
map in the script); `strings_app.xml` comes from `tools/strings/app_strings.yml` for
the few strings only the app needs. Plurals get `one/few/many/other` for sk/cs and
`one/(many)/other` for en/es. `StringsParityTest` fails if a language lacks a string,
changes a placeholder, or misses a plural form.

## Architecture

Single activity (`MainActivity`, AppCompat for per-app language on old Android),
Jetpack Compose + Material 3 (dynamic colour, purple-600 fallback), Navigation
Compose with a bottom bar (Dashboard, Channels, Events, Ask, More) or a navigation
rail on wide screens.

```
data/api      Retrofit interface (LievikApi), kotlinx.serialization models (snake_case),
              ApiClient (OkHttp, server rewrite, auth + Accept-Language headers, SSE via
              okhttp-sse), ApiError (sealed: Unauthorized, Paywall, DailyCap,
              BillingUnavailable, Validation, RateLimited, NotFound, Refused, Network, Server),
              StreamEvents (phase / chunk / proposal / complete / error)
data/db       Room: sources, channels, events, channel_events, contents; CurationQuery /
              EventsQuery (the web's filters as SQL); SyncMerge
data/repo     SyncRepository, Session (token), Messages (app-wide snackbar/billing bus),
              Connectivity
data/prefs    DataStore prefs (server URL, sync cursor, cached /meta and /me) and
              SecureStore (API token, AES-GCM key in the Android Keystore)
nostr         NIP-55 intents, the kind-22242 auth event, bech32, nostr: reference rendering
ui            screens per area, shared components (EventCard, NostrContentView,
              Markdown renderer, chat, billing banner/dialog)
AppContainer  manual DI; ViewModels get it through appViewModel { … }
```

Errors go through one place: every failure becomes an `ApiError`, and
`Messages.forError` turns it into a snackbar or, for 402 paywall / 429 daily_cap /
503 billing_unavailable, the billing dialog with "See plans". A 401 on a request
that carried a token signs the device out (the HTTP interceptor does it).

On every start/resume the app calls `/meta`: below `android.min_version_code` it
shows a blocking "update required" screen with the download link; below
`latest_version_code` a dismissible banner. `billing_enabled: false` hides the
whole billing area.

## Login

Sign-in is the shared `nostr-signin` module in `nostr-signin/`, a vendored copy of
`~/projects/nostr-signin-android` that Emanator's app uses too. **Do not edit it
here:** change the source repo and run its `sync.sh`. This app supplies only the
screen and `LievikSignInBackend` (the module's `SignInBackend` over Retrofit).

Three ways, all ending in a per-device API token (`App: <device name>` in the
web's token list):

1. **Signer on this phone (NIP-55, Amber and others).** `get_public_key` through an
   intent (asking permission for kind 22242), `/auth/challenge`, a kind-22242 proof
   signed through the signer's content provider (silent once permitted) or, failing
   that, its `sign_event` intent launched only after this screen is resumed, then
   `/auth/token`.
2. **NIP-46 nostrconnect.** `/auth/nostrconnect` → the `nostrconnect://` URI opens in
   the signer app (or shows as a QR for a signer on another device);
   `/auth/poll` every 2 s until `authenticated` or `expired`.
3. **bunker:// paste.** `/auth/bunker`, then the same polling.

The server URL (default `https://lievik.cypherpunk.today`) is under **Advanced** on
the login screen, for self-hosted instances. After login the app adopts the
language saved on the user if it has none of its own; changing the language in
Settings also saves it on the user (`PATCH /me`).

## Sync

`SyncRepository` keeps Room in step with `GET /api/v1/sync`:

- first run: no `since`, pages through `cursor` (later pages send only the cursor);
- afterwards: `since` = the stored `server_time` of the last completed run;
- each page: the source and channel tables become the returned lists; events of
  sources that disappeared and ratings of channels that disappeared are deleted;
  everything else is upserted (idempotent, so the server's 5 s overlap is harmless);
- an interrupted first sync resumes from the stored cursor; a rejected cursor/since
  (422) restarts the window.

It runs on app start/resume, pull-to-refresh, after mutations, and every 30 minutes
in a WorkManager job (network required). Settings has "Download everything again"
for a full resync.

Screens read Room flows: the curation queue applies the web's semantics locally
(at or above the channel threshold, unused unless "show used", used pinned to the
bottom, sort by rating/newest/oldest, substring search), and also fetches page 1
of the current filters from the server so events older than the sync window still
appear. Mark used / unused is optimistic and rolls back if the server refuses.
Online-only features (AI, billing, activity, event details with reasons) show an
offline state without a connection.

## Release

Release builds are minified with R8. Signing is optional and the key never lives
in the repo: when `~/.apk-signing-keystore/signing.properties` (or the file named by
`APP_SIGNING_PROPERTIES`) exists, with `storeFile`, `storePassword`, `keyAlias` and
`keyPassword`, Gradle signs the release with it. Otherwise the release APK is built
unsigned and can be signed separately with `apksigner`.

```sh
./gradlew assembleRelease     # app/build/outputs/apk/release/app-release.apk (or -unsigned.apk)
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --print-certs app/build/outputs/apk/release/app-release.apk
```

The published builds are signed with the certificate
`79750fb49349ec3729be5a3e825507a15e47c6d987e854ae91d5d50a20b3a24d` (SHA-256).

Then publish as with the other apps (the `zapstore-android` flow: shared publisher
key, `zsp publish`, download page / Obtainium). Bump `versionCode`/`versionName` in
`app/build.gradle.kts` for every release, and set `ANDROID_LATEST_VERSION_CODE`
(and `ANDROID_MIN_VERSION_CODE` when an old build must stop working) plus
`ANDROID_DOWNLOAD_URL` on the server so installed apps learn about it.

The app is meant for Zapstore, Obtainium and direct APK download, not Google Play:
Play's payment policy would require Google Play Billing for the paid plan, so the
app opens BTCPay's checkout (`checkout_url`) in a Custom Tab instead and polls
`GET /billing/charges/:invoice_id` until the invoice settles.
